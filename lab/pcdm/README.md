# PCDM Core+MCP evidence runner (public transport only)

**Current status: `BLOCKED_INPUT`, not a cosmological sampling run.** The public repository has no verified native PCDM scalar dynamics, complete CMB+BAO+megamaser likelihood, numerical nuisances, normalized log-likelihood nor frozen priors needed to compute Bayesian evidence. The nine-point profile is **not** a set of posterior samples. No prior ranges are inferred from optimization endpoints. Never put PEER, private Drive material, secrets, blinded material or Olympus here.

The isolated [Actions workflow](../../.github/workflows/nexo-pcdm-ns.yml) implements resumable `dynesty==2.1.5` with a **280-minute scientific window** per segment, extra conservative within-window saves every 600 seconds, and an immutable end-of-segment artifact (SHA256-checked). On non-convergence it can dispatch the next workflow at the *same commit*, download the previous artifact and verify contract, adapter, runtime version and checkpoint checksums. Up to `max_segments`, then it stops. Each Actions job has a 340-minute outer limit to allow package setup and artifact upload. Continuation is not guaranteed if GitHub dispatch or artifact retention fails; the checkpoint remains available for manual recovery.

## Required physical binding

Supply a **public and fully sanctioned** `real_adapter.py` exposing two pure functions: `loglikelihood(theta)` returning the real cosmological **log likelihood** (not a mixed negative log posterior / objective), and `prior_transform(unit_cube)` returning the frozen prior transform. Its implementation must contain identical correct nuisance marginalization and correlated official covariance handling for both PCDM and ΛCDM. The config's `adapter` is relative to this folder, and `adapter_sha256` must be its calculated SHA-256. The `data_sha256`, `likelihood_sha256`, `priors_sha256` keys are SHA-256 provenance identifiers for independently archived versioned manifests (not placeholder hashes). Freeze `ndim`, `nlive`, `seed`, `dlogz`, and `max_segments`; set `status: READY_PUBLIC_INPUTS` only after validation. Sampling one fixed `n` is a **conditional** evidence, not evidence for a scanned/continuous `n`. ΛCDM baseline and prior-mass weighting of all nine cells must be independently planned before claiming a Bayes factor.

Run `python -m unittest discover -s lab/pcdm/tests -v`. The synthetic test tests only checkpoint and resume, not the physical fit. The workflow has no default schedule and cannot run production before its source exists on the repository's default branch and the binding passes. PR checks do not execute a scientific PCDM run. Results are `CONVERGED` only after finishing live points; `RUNNING` is never labeled a Bayes-factor result.
