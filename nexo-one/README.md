# NEXO ONE

Personal cockpit in `Pantheon/nexo-one`. React 19, TypeScript, Vite, Node 24. No database. Existing Atlas is unchanged.

## Current scope

Five views (NOW, LOOPS, DAY, CONTEXT, RECALL), dark/light responsive shell, command parser, modal focus panel, provenance validation, seven isolated read adapters, bounded parallel compilation, incremental NDJSON delivery, last-valid warm-instance cache, semantic world diff, explicit source coverage, single-user signed session cookies.

**This is an integration candidate, not an operational V1.** Public GitHub has been verified live. Private Calendar/Drive/Gmail, the canonical NEXO export, Atlas graph access and Vercel runtime credentials remain unconfigured. No private user records or test fixtures are bundled or exposed publicly. The Atlas launcher opens its existing application; the graph adapter understands its existing V1 envelope. It does not embed a new graph renderer.

## Run

```sh
cd nexo-one
npm ci
npm run check
npm run dev
```

Node 24 is required (native type stripping for pure TypeScript model tests). Local dev binds to 127.0.0.1:4173. `npm run preview` serves the production build. If your remote browser cannot access localhost, use a verified deployment for visual interaction.

Server tests use synthetic fixtures only in `test/`; UI production never substitutes them for an unavailable provider. Browser CI installs pinned Playwright in an isolated tool directory; `PLAYWRIGHT_MODULE` can select that installation. Its route fixtures do not enter the deployed app.

## Configure private access

See `.env.example` for **names only**. Provision these directly in the existing `nexo-one` Vercel project; never in chat, source files or client-prefixed variables.

1. Set `NEXO_SESSION_SECRET` (at least 32 random characters) and `NEXO_PASSWORD_HASH` (scrypt format generated by `scripts/password.mjs` reading stdin). Protect `/api/session` with a platform rate limit as well; the implemented rate bound is per warm instance. Password login is an initial single-user gate, not a complete identity-management service.
2. Google OAuth read-only scopes: `drive.readonly`, `gmail.readonly`, `calendar.readonly`; set client ID, client secret and refresh token after owner consent. There is no in-app OAuth onboarding flow yet. Token exchanges remain server-side. The ChatGPT connectors are not application credentials. Optional Drive folder restriction and Calendar ID are in the env template.
3. GitHub: defaults to the public `byDenoso/Pantheon` repository without a token. Private mode can use a fine-grained read token. Open issues/PRs are bounded to 100; the UI reports partial coverage. RECALL searches issue/PR content and repo metadata; it does not yet search every code file.
4. Vercel: set a read credential, team ID and the exact project ID. This is a read adapter; no deployment action is exposed by the UI.
5. NEXO: point `NEXO_SOURCE_URL` to an **existing owner-authorized export** `{version:"1", revision:"...", items:CockpitItem[]}`. Do not create or designate a new truth owner to satisfy this input. Dates, statuses and origin links are validated. No heuristic rewriting of canonical registers.
6. Atlas: `ATLAS_GRAPH_URL` is the existing authorized Graph Contract V1 URL. Add `ATLAS_SOURCE_TOKEN` only if that API expects a bearer credential. Private graph reads require a valid NEXO ONE session. No Neon connection is added.

After configuring providers, redeploy to staging and verify authenticated live reads and unauthenticated non-disclosure. Review credential scope and viewer access before releasing any private integration.

## API

`GET /api/world` compiles all available providers. `?stream=1` emits one WorldState per completed provider, allowing the shell to render fast sources first. `?refresh=1` bypasses the short cache; concurrent snapshots are coalesced. Every reader has an 8-second outer deadline even if it ignores AbortSignal.

`GET /api/health`, `/api/now`, `/api/loops`, `/api/day`, `/api/context?id=NEXO`, `/api/recall?q=...` are projections. Calendar fetches a rolling two-week window; choosing a day outside it does not imply that day is free. Query strings contain search text, not credentials. API responses use `private, no-store` and `Vary: Cookie`.

`GET/POST/DELETE /api/session` reads/creates/clears the signed HttpOnly session cookie. Private reads are gated **before** adapter invocation. Public mode never passes a private token to GitHub and never serves a private cache entry. Authentication loss discards the affected private provider cache. All other non-GET requests are rejected; email, calendar and source writes are disabled.

## Semantics and limits

- NOW uses explicit due dates, assignment, priorities and blocked state. Unread messages do not create commitments. Closed events do not become overdue tasks. Cached/stale items cannot assert live urgency.
- Provider count is `null` on unavailable reads, `0` only after a valid empty result. Successful bounded reads carry `partial` when more pages exist.
- World fingerprints exclude polling timestamps, preserve content/source revisions, include freshness and availability, and are stable under provider/item order. Diffs compare completed reads; removal from the view is not asserted as deletion at the owner.
- NEXO observations are not re-dated on read; Atlas FALLBACK/STALE is carried through. Context inference from names is derived navigation, not a scientific claim.
- Last-valid cache is **ephemeral server memory** and the active browser session; it is not cross-device persistence or a new canonical store. Only UI theme/tab are stored locally. On reload/cold start, sources must be fetched again. Auto-refresh runs every 5 minutes while visible and on returning to a stale tab; there is no background automation.
- DAY displays fixed events, overlap indicators and unassigned flexible work. Duration-aware allocation, recovery-margin calculation and manual focus persistence are not implemented.
- Manual loops, snooze/pin/dismiss persistence, email drafts, calendar proposals and all provider writes remain disabled. Secondary tabs and later roadmap features are not implemented.
- Initial browser screenshots require baseline review before visual regression can claim an approved baseline. The CI generates screenshot evidence, not a fabricated visual approval.

## Deployment and rollback

The only project is `nexo-one` (`prj_rFoAEgGt4gFNr8DHEOzxY7keS16W`). `scripts/package-release.mjs` packages the exact built assets and dependency-free server, with a SHA-256 file manifest. It excludes fixtures, secrets and node_modules.

The connector's first deployment was requested as preview but returned `target: production` on readback (initial project autoassignment). Only public GitHub was enabled. This does **not** prove the requested preview → verify → same-artifact promotion pipeline. Do not treat a green build as promotion acceptance.

`.github/workflows/nexo-one-ci.yml` runs types, unit/adapter/security tests, desktop/mobile browser scenarios and packages immutable release artifacts. Deployment workflows are manual, scoped to the same project, and require dedicated secrets and environment approval. Production uses a staged production build before `vercel promote` so there is no rebuild between staging verification and promotion. See `docs/RELEASE.md`.

Sources used for the integration design: [Google server-side OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [GitHub Issues REST](https://docs.github.com/en/rest/issues/issues), [Vercel deployment creation](https://vercel.com/docs/rest-api/deployments/create-a-new-deployment), [Vercel staged production promotion](https://vercel.com/docs/deployments/promoting-a-deployment).
