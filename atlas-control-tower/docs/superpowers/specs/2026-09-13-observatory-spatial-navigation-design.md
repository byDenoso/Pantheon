# Observatory Spatial Navigation Design

## Goal

Make Observatory the primary spatial navigation surface of NEXO Atlas. Remove the separate top-level Graphs product area while preserving legacy graph deep links. The user should feel they are navigating inside the Observatory, not switching to a graph feature.

## Product model

Primary navigation becomes:

- Observatório
- Laboratório
- Resumo do Universo

The graph remains the core navigation mechanism inside Observatório. The renderer is PixiJS Canvas 2.5D by default and presents semantic depth through projection, scale, opacity, parallax, camera motion and Z roles. WebGL/Three is not exposed as a normal product mode.

## Routing

`/graphs` and all existing `/graphs/...` URLs remain accepted as compatibility inputs. `readAtlasRoute` normalizes them to `area: observatory` while preserving graph path, domain, query and other declared context. New links generated by `routeFor` use `/observatory` only.

Examples:

- `/graphs` -> `/observatory`
- `/graphs/science/d7` -> `/observatory?domain=D7` with graph path preserved in route state/query when needed
- saved entity/search context remains attached to Observatory

Back/forward must restore the same Atlas session navigation stack and browser route context.

## Observatory composition

Observatory owns the full-bleed graph workspace. The graph is not nested in a card. The main layers are:

1. Context Bar
2. Full-bleed Canvas 2.5D graph
3. Spatial HUD for browser navigation, camera, zoom, perspective, LOD and focus
4. Spatial Inspector on desktop / bottom sheet on mobile
5. Retractable observational signals drawer for H0, tensions, directional signals and universe snapshot
6. Minimap/context strip

Scientific panels remain read-only projections and never become graph truth.

## Spatial semantics

Preserve and strengthen:

- Ancestor Shell: behind focus, lower contrast, smaller scale
- Current Space: focus and immediate children/relations at primary depth
- Relation Horizon: lateral relations with reduced emphasis
- Portal nodes: explicit cross-domain jumps with distinct treatment

Navigation is continuous. Entering a node advances semantic depth and animates the camera rather than replacing the whole scene abruptly.

## Camera and projection

Create pure, testable 2.5D camera helpers. Camera state contains:

- x
- y
- zoom
- yaw
- pitch
- depth
- perspective preset: flat | balanced | deep

Pure functions include world/screen projection and depth scale/opacity. Pointer parallax is bounded and disabled for reduced motion. Balanced is default.

## Controls

Desktop HUD supports back, forward, home, zoom out/in, center/reset, perspective preset, semantic LOD, focus mode and minimap. Existing mouse drag, wheel zoom and touch pinch/pan remain. Keyboard includes Alt+Left/Right, Backspace, Home, +/-, F and Escape where they do not conflict with editable controls.

Touch targets are at least 44 px. Mobile uses a compact bottom dock and inspector bottom sheet.

## Renderer policy

`GraphRenderer` always selects Canvas/Pixi for the product path. Experimental Three/WebGL files may remain temporarily for rollback/tests but no normal UI switch exposes them. `app.destroy(true)` must never return. Normal teardown uses local destruction with `releaseGlobalResources: false`.

## LOD and labels

Semantic LOD remains Macro, Meso, Micro and Detail. Focus, selected, pinned and required ancestor context are never dropped. Label priority is focus, selected, pinned, near ancestor, relevant child, then remaining budget. Canonical IDs stay in Inspector, not primary labels.

## Inspector and search

Spatial Inspector follows selection. Search results navigate to Observatory, center/focus the selected entity when resolvable, preserve context and open the inspector. Pin and Compare stay available from the spatial surface.

## Mobile

On narrow screens Observatory uses:

- compact header
- short Context Bar
- full-height Canvas using `100dvh`
- safe-area aware bottom navigation dock
- inspector bottom sheet with collapsed/medium/full states
- no horizontal overflow

Canvas gestures remain available when the inspector is collapsed.

## Observational overlays

Existing Observatory scientific panels are preserved as a retractable signals surface instead of a card wall below the graph. The graph remains visually dominant. No missing synthesis or scientific values are invented.

## Error and lifecycle behavior

The Observatory must survive Observatory -> Lab -> Observatory, Observatory -> Universe -> Observatory, deep links, back/forward, StrictMode remount and mobile Safari. A graph error remains local and never produces a blank app.

## Testing and release

TDD contracts cover top navigation, legacy route normalization, Observatory ownership of the canvas, Canvas-only renderer policy, 2.5D camera math, reduced-motion behavior, search-to-Observatory, mobile layout and Pixi lifecycle.

Pages browser smoke must open Observatory, wait for a real Pixi canvas, select/navigate, use back, visit Lab, return to Observatory, verify remount, and fail on page errors or retired runtime calls.

## Definition of done

- No Graphs top-level tab
- Observatory is the graph navigation surface
- `/graphs` deep links remain compatible
- Canvas/Pixi 2.5D is the product renderer
- 2.5D perspective/camera controls exist
- Spatial context, inspector, LOD, pin/compare and back/forward work inside Observatory
- Mobile is full-height and overflow-safe
- Pixi lifecycle regression remains fixed
- tests, typecheck, build, Pages lifecycle smoke and public readback pass
