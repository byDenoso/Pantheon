# Atlas 2.5D CSS Graph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the primary R3F orbital graph renderer with the approved DOM + SVG + CSS 2.5D visual while preserving projection data, learning overlays, selection, drill-down behavior, and explicit 3D/2D rollback routes.

**Architecture:** `GraphRenderer` becomes the gateway for three renderers: CSS 2.5D by default, legacy R3F via `?renderer=3d`, and Pixi via `?renderer=2d`. The 2.5D scene uses deterministic semantic layout, HTML/CSS spheres and labels, SVG curved edges, orbit/cluster overlays, bounded tilt/zoom, and the existing selection callbacks.

**Tech Stack:** React 19, TypeScript 5.9, SVG, CSS 3D transforms, React Router, Node test runner.

**Spec:** `atlas-control-tower/docs/superpowers/specs/2026-09-11-atlas-3d-graph-engine-design.md` plus the approved standalone CSS 2.5D concept from the implementation session.

## Global Constraints

- Keep `GraphProjection` and existing data-loading paths unchanged.
- CSS 2.5D is the default renderer.
- `?renderer=3d` keeps the existing R3F renderer available during rollout.
- `?renderer=2d` keeps the Pixi fallback available.
- Layout must be deterministic and semantic; no force-layout randomness.
- Focus nodes must visually dominate domain, subgraph, entity, and auxiliary nodes.
- Labels are priority-budgeted; secondary labels appear on interaction rather than all at once.
- Respect `prefers-reduced-motion`.
- Do not remove the existing R3F scene during this rollout.
